# HUMAN_TEST procedure

1. Register a disposable external Git project and verify overlap rejection for
   the ForgeFlow and run roots.
2. Select each of the five screens and confirm only its fixed events appear.
3. Select representative query, command, navigation, and export events; confirm
   unrelated requirements/tables/APIs/files/methods show zero.
4. Edit all ten harness drafts, switch agents, publish atomically, reload, and
   verify content/version/diff.
5. Confirm all B controls are blocked before design approval.
6. Run A, inspect requirements/mockup/data/API/review evidence, approve a snapshot,
   and confirm the event queue.
7. Run B against the disposable target using the fake adapter, then the isolated
   real adapter; inspect changed paths, patch, build/tests, findings, token ledger.
8. Reopen A and verify queue items and every prior PatchBundle become STALE.
9. Approve again, reach score gates, inspect the patch, and reject once; verify no
   target change and state does not become ACCEPTED.
10. Approve HUMAN_TEST, dry-run/apply, verify revision and audit, then execute the
    recorded rollback and regression.

Record actor, timestamps, revisions, commands, exit codes, hashes, screenshots,
and artifact IDs. HUMAN_TEST is incomplete until a person signs the gate.
