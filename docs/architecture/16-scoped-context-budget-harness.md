# Scoped Context Budget Harness

## Compatibility boundary

The browser, `/api/v1/**` controllers, request/response records, event manifest,
and harness editing surfaces are unchanged. `RunController` still invokes
`WorkerRuntimeService.executeFake(runId)`; that internal method now enters the
Generator Kernel.

## Existing-to-new mapping

| Existing component | New responsibility |
| --- | --- |
| `WorkerRuntimeService` | API-compatible Kernel entry point |
| `WorkerSupervisor` | Per-run worktree and control-plane separation |
| `PathGuard` | Low-level real-path containment |
| `PatchValidator` | Patch path validation retained |
| `CodexCliWorkerAdapter` | Legacy direct-host adapter, fail-closed by default |
| none | `TaskNormalizer`, immutable `TaskContract` |
| none | incremental `RepositoryMap`, tiered `ContextBuilder` |
| none | `TokenBudgetController`, `ModelRouter` |
| none | `PolicyEngine`, bounded `ToolGateway` |
| none | deterministic `Verifier`, conditional `WorkflowController` |
| none | isolated `GitController`, `DockerSandboxCommand` |

## Execution contract

The Kernel sends one `AgentEnvelope` to one role at a time. Results must match
the task and role in the JSON envelope; agents have no messaging channel.
Low-risk passing work executes Worker only. High-risk or failing work adds
Reviewer; high-risk work first executes Explorer and Planner to establish the
bounded context and write scope. Verification always runs after Worker. Failing
checks permit at most two Repairer attempts, and two identical failures stop the
run with the current evidence.

Repository context is selected in this order: incremental repository map,
search-selected symbols, bounded ranges, and only then a complete relevant
file. The builder includes policy, Task Contract, selected map entries, selected
symbols/contracts, and the previous structured result. Token and tool-output
budgets fail closed.

## Isolation and publication

The only worker bind mount generated by `DockerSandboxCommand` is:

`generated-projects/{projectId}/worktrees/{runId}:/workspace`

The command disables networking, uses a read-only container root, drops every
capability, enables `no-new-privileges`, and sets PID, memory, CPU, and time
limits. Images must be pinned by SHA-256 digest and the worker runs as UID/GID
65532 with a bounded no-exec tmpfs. Agent stdout must be a matching
`AgentEnvelope.Result` JSON document and stdout/stderr are each limited to 1 MiB.
`PolicyEngine` rejects absolute task scopes, traversal, denied names,
external links, symlinks, and reads/writes outside the contract.

`WorktreeController` verifies the requested base commit, rejects `.gitmodules`,
and creates a detached worktree only at
`generated-projects/{projectId}/worktrees/{runId}`. The target repository and
control-plane roots are never worker mounts.

Agents cannot publish. After all deterministic checks pass, `GitController`
stages each explicitly allowed changed file, commits, and pushes only a
`task/*` branch. Verification, missing required review, or policy failure
produces no Git command. Force push and direct protected-branch publication are
unavailable. A Clean Checkout CI adapter must report PASS before the publish
result can become merge-eligible.

Each invocation writes token counts and duration to `token_ledger`; tool-call
count, tool-output characters, role, and adapter are written to the audit log.
The default remains the deterministic fake adapter for API compatibility and
tests. Production Docker execution is opt-in through `FORGEFLOW_WORKER_MODE`,
and requires a digest-pinned `FORGEFLOW_WORKER_IMAGE`.
