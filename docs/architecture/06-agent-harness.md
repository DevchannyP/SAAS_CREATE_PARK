# 06. Agent harness

Both loops use deterministic L0 governance, read-only L1 coordination, L2
single-writer specialists, isolated L3 critics, and L4 human gates. The UI exposes
only five design and five code specialists from the fixed harness paths.

Design runs D00–D10: requirements precede parallel mockup/data work; API consumes
both; review emits FindingPackets to artifact owners; snapshot approval is human.
Code runs C00–C12: snapshot validation precedes scoped repository mapping and an
ImplementationPlan; non-conflicting owners write; tests and independent critics
produce evidence; PatchBundle precedes HUMAN_TEST.

Harness saves validate identifiers, required sections, forbidden capabilities,
iteration limits, and gates, then publish all edited files atomically as one
version. Drafts are user-scoped and do not affect active versions.

The publish contract is all-or-nothing: an unknown agent, blank content, or
forbidden capability rejects the complete request; no subset of files is stored.
